# ATF: переход к первому пробнику

Точный ATF из tee_b: SHA-256 `ef838aa754b367a0cfef4d18272d812895bb28aa55525b6a672245f223ca4935`, 962168 байт. Происхождение и совпадение stock/captured prefix — `evidence/extracted/2026-09-14/atf-analysis/manifest.json`. Дизассемблировка воспроизводится `python tools/extract_atf_handoff.py`.

Таблица по смещению `0x67ea0` содержит указатель handler `0x4880c724`, SMC IDs `0x82000115`/`0xc2000115`, указатель на `MTK_SIP_KERNEL_BOOT`. Размер записи 32 байта. Диспетчер `0x4882d878..0x4882d8c0` перед косвенным вызовом сдвигает аргументы: handler получает kernel target, DTB, 0, 1 в x0..x3. После вызова его результат записывается в x0 сохранённого контекста, дополнительное значение — в x1.

Handler сохраняет kernel target и DTB, а затем вызывает `0x4880bf44` с x0=1. В AArch64-ветке этой функции в поле SPSR создаваемого контекста записывается `0x3c9`, если ID_AA64PFR0_EL1 сообщает EL2, иначе `0x3c5`. Это соответственно EL2h/EL1h с масками DAIF. Handler возвращает DTB как результат и 0 как дополнительное значение, что согласуется с Linux-style x0=DTB, x1=0.

Это статический разбор ветки, а не измерение на входе пробника. Функция имеет ранний выход после проверки `0x48821ec0`; полный эффект всех платформенных hooks и hypervisor здесь не доказан. Поэтому пробник сохраняет реальные x0..x3, проверяет CurrentEL и SCTLR самостоятельно. При EL3, включённых MMU/D-cache или big-endian он останавливается до записей. Эти проверки нельзя убирать ради появления картинки.

Предэкспериментальная граница: образ не отключает watchdog и не программирует DSI, GPIO, EMI или PMIC. Он использует стек внутри распакованного payload и делает ограниченные записи только в подтверждённую поверхность framebuffer. Возможность записи и обновление панели после handoff ещё проверяются самим первым аппаратным опытом. Отсутствие метки остаётся неоднозначным: это может быть отказ загрузки, неподдержанное состояние входа или отсутствие обновления панели.
